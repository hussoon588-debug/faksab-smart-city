## ✂️ ابدأ النسخ من هنا

### 0· دورك والسياق

أنت المهندس الرئيسي (تصميم + معمارية + تنفيذ) للعبة «**أفق**» — مدينة عقارات افتراضية
بالعربية أولاً. لديك مستودع قائم يعمل، وليس مشروعاً من الصفر. مهمتك إعادة بناء الطبقة
الظاهرة وإكمال الوظائف الناقصة **دون كسر** ما يعمل، ودون ادعاء أي شيء غير موصول.

**قاعدة الحكم الأولى:** إذا لم يكن الشيء موصولاً بخادم حقيقي أو محسوباً في الكود، فلا
يُعرض كأنه كذلك. لا أزرار وهمية، ولا أرقام مزخرفة، ولا شارة «متصل» بلا جلسة.

### 1· الحالة الحالية — لا تُعِد بناءها

الموجود والمُختبَر (49 اختباراً، 50 ملفاً مدقّقاً، بناء إنتاجي ناجح):

- `apps/ofuq/src/core.js` — اقتصاد حتمي نقي (أسعار، إيجار، ترقية، قيمة، بيع، مستويات، مهام).
- `apps/ofuq/src/store.js` — الكاتب الوحيد للحالة، إجراءات تُعيد `{ ok, message }`، حفظ
  مُصدَّر بـ `schemaVersion`، وفي وضع الخادم يرسل **النية فقط** ويتبنّى اللقطة العائدة.
- `apps/ofuq/src/ui.js` — عرض من لقطة المتجر، تفويض نقرات عبر `data-action`، بلا معالجات
  سطرية وبلا متغيرات عامة (لتمكين CSP صارمة لاحقاً).
- `apps/ofuq/src/remote.js` — محوّل Supabase بلا اعتماديات، رسائل خطأ عربية آمنة للاعب.
- `supabase/ofuq/schema.sql` — المخطط الكامل: كتالوجات، محافظ، **دفتر قيود غير قابل
  للتعديل**، 100 قطعة مبذورة، RLS، وست دوال معاملات.
- PWA: مانيفست + عامل خدمة بإصدار كاش + أيقونات + خط Cairo محلي (بلا CDN).
- بوابات `npm run check | test | build | verify` + CI + تدقيق أمني يرفض المفاتيح السرية.

**اللوحة الحالية منشورة** (`3000-…e2b.app`) وهي مرجع للشكل فقط، ومليئة بأخطاء يجب
تصحيحها لا محاكاتها: رصيد 430 مقابل سجل −1,920، «3 قطع» مقابل «8 مسجلة»، إيجار يُخصم
بدل أن يُضاف، وشارة «متصل بالخادم» بلا أي حساب.

### 2· الهوية البصرية

- **الطابع:** مدينة خليجية عند الغروب — رمل دافئ، ظل أزرق عميق، ذهبي للقرارات المالية.
  لا ألوان نيون، لا تدرّجات بنفسجية، لا أيقونات عائمة بلا معنى.
- **الطباعة:** Cairo (محلي). مقياس واضح: 12/14/16/20/28/40. أرقام لاتينية مع تنسيق عربي
  (9,999 و12.5K)، والأرقام دائماًtabular حتى لا ترتجف أثناء التحديث.
- **الشبكة:** 8px أساس. حشوة شاشة 20px على الهاتف. نصف قطر 14px للبطاقات، 20px للألواح.
- **الحركة:** 180ms `ease-out` للفتح، 120ms للإغلاق، انتقالات ارتفاع 220ms. لا حركة
  تتجاوز 320ms. احترام `prefers-reduced-motion` إلزامي.
- **الحالات:** محايد، هامش (رملي)، نجاح (أخضر زيتوني)، خطر (طوبي)، مقفل (رمادي مع قفل).
  كل حالة تحمل **نصاً** لا لوناً فقط (لعمى الألوان).
- **اللمس:** أصغر هدف 44×44px، تباعد 8px، وردّ فعل `navigator.vibrate` اختياري (كما هو).

### 3· المعمارية — أين تعيش الحقيقة

- **الخادم هو مصدر الحقيقة** للملكية والرصيد والخبرة والمهام. العميل **يعرض** و**يقترح**.
- كل تعديل يمرّ بدالة RPC واحدة داخل معاملة، تكتب **صف دفتر واحداً**، وتُعيد اللقطة كاملة.
- القاعدة الذهبية: **لا يوجد في العميل أي مسار يكتب رصيداً.** حتى في الوضع المحلي،
  الحساب في `core.js` هو محاكاة مطابقة، لا مصدر سلطة عند وجود جلسة.
- `idempotency`: كل طلب تعديل يحمل مفتاحاً فريداً؛ `unique(player_id, idempotency_key)`
  في الدفتر. إعادة المحاولة بعد انقطاع الشبكة = **لا شيء**، لا خطأ ولا خصم مضاعف.
- الفصل في المتجر: الوضع المحلي **متزامن** (النقرة تُحدّث الواجهة في نفس الدورة)، ووضع
  الخادم **غير متزامن** ويعتمد ردّ الخادم. لا تدمج المسارين.
- كل خطأ يُترجم إلى جملة عربية يفهمها اللاعب وتقول هل خُصم منه شيء («لم يُخصم منك شيء»).

### 4· الاقتصاد — أرقام ثابتة (لا تُغيّرها بلا قرار صريح)

| البند | القيمة |
| --- | --- |
| الرصيد الابتدائي | 12,000 وحدة (سبب الدفتر `signup_bonus`) |
| سعر القطعة الأساسي | 400 × تصنيف الحي، مقرّب لأقرب 50 |
| الأحياء | `harbor` 1.0 · `garden` 1.15 · `downtown` 1.35 · `tech` 1.6 · `horizon` 2.0 |
| فتح الأحياء | بالمستوى 1 / 1 / 2 / 3 / 4 — كل حي 20 قطعة (100 قطعة) |
| الأصول | استوديو 1,400 (34/س) · متجر 2,800 · مكتب 5,600 · ضيافة 9,800 |
| الإيجار | `rent × (1 + 0.35×(level−1)) × (1 + 0.15×(tier−1))` لكل ساعة |
| سقف التحصيل | **8 ساعات** — ما بعدها لا يتراكم (يمنع الغياب الطويل كاستثمار) |
| ترقية | `cost × 0.55 × level ÷ tier`, مقرّب لأقرب 50، حتى المستوى 5 |
| قيمة البيع | `price + cost×(1+0.35×(level−1))×0.9` ثم **×0.96** (رسوم سوق 4%) |
| الخبرة | شراء 40 · تطوير 120 · ترقية 90 · تحصيل 6 · بيع 50 |
| المستويات | 0 / 700 / 1,800 / 3,600 / 6,000 / 9,000 خبرة |
| العملات | **واحدة فقط** (وحدة) + سمعة. لا عملات ثانية، لا NFTs، لا بلوكشين |

قواعد اقتصادية إلزامية:
1. **مصدر دخل واضح**: الإيجار دخل يُضاف للمالك عند التحصيل، وسقفه 8 ساعات.
2. **لا أصفار ميتة**: أي قطعة بلا أصل لا تدرّ شيئاً، ويجب أن تقول الواجهة ذلك.
3. **رسوم معلنة**: 4% عند البيع تظهر في شاشة التأكيد قبل التنفيذ.
4. **الدفتر كامل ولا يُحذف**: بنوده `signup_bonus, plot_purchase, development, upgrade,
   rent, sale, mission_reward, market_fee, admin_adjustment`. أي رصيد يمكن تفسيره بجمع بنوده.

### 5· نموذج البيانات

- `ofuq_players` (معرّف، اسم، خبرة، سمعة، أسبوع إعادة الضبط)
- `ofuq_wallets` (رصيد) + `ofuq_ledger` (الدفتر: المبلغ، السبب، المرجع، مفتاح عدم التكرار)
- `ofuq_districts` (المعرّف، الاسم، التصنيف، مستوى الفتح)
- `ofuq_assets` (المعرّف، الاسم، التكلفة، الإيجار، مستوى الفتح)
- `ofuq_plots` (الحي، رقم القطعة، المالك، الأصل، المستوى، السعر، آخر تحصيل) — فريد (الحي، الرقم)
- `ofuq_missions` + `ofuq_claims` (هدف، مكافأة، حد أسبوعي، منع الاستلام المزدوج)
- `ofuq_weekly_stats` (مؤشرات لوحة الصدارة)

### 6· واجهة الـRPC (عقد لا يتغيّر شكله)

```
ofuq_snapshot()                                        → لقطة كاملة
ofuq_purchase_plot (p_district, p_plot_no, p_idempotency)
ofuq_develop_plot  (p_plot, p_asset,      p_idempotency)
ofuq_upgrade_plot  (p_plot,               p_idempotency)
ofuq_collect_rent  (p_plot,               p_idempotency)
ofuq_sell_plot     (p_plot,               p_idempotency)
ofuq_claim_mission (p_mission,            p_idempotency)
```

- كل تعديل يُعيد **اللقطة كاملة** — لا يعيد العميل تخمين الحالة.
- إعادة محاولة بمفتاح سبق تسجيله = `return ofuq_snapshot()` قبل أي تحقق من الملكية
  (وإلا عاد خطأ «مملوكة بالفعل» لطلبٍ نجح فعلاً).
- التحقق داخل المعاملة و`for update` على القطعة: نافذتان لا تشتريان قطعة واحدة.
- أخطاء مفهومة بالعربية مع `errcode` مناسب.

### 7· الشاشات — بالأولوية

**المرحلة أ (ضروري للانتقال من العرض إلى لعبة حقيقية):**
1. **الدخول**: بريد + كلمة مرور، دخول/إنشاء حساب، استعادة الجلسة عند الإقلاع، شاشة
   «بحاجة لتسجيل الدخول» بدل شارة كاذبة. الحساب اختياري في الوضع المحلي، إلزامي في المشترك.
2. **الخريطة**: خمسة أحياء كشرائح أفقية، كل قطعة بطاقة صغيرة بحالة ونص عربي، تكبير/تحريك
   بالإيماء، بحث برقم القطعة (`OF-014`)، مرشّح (متاح/مملوك/للبيع)، خريطة مصغّرة ثابتة في
   الزاوية. ضغط مطوّل = معاينة، نقرة = لوحة الإجراءات.
3. **لوحة القطعة**: صورة/رسم الأصل، الإيجار الحالي، التحصيل المتاح مع سقف الـ8 ساعات،
   الترقية مع التكلفة القادمة، البيع مع صافي المبلغ بعد الـ4%، وسجل القطعة من الدفتر.
4. **المحفظة**: رصيد + كل بند دفتر بالتاريخ والسبب، مع تصفية، ومجموع مطابق للرصيد.
5. **التقرير الأسبوعي**: الدخل، المصروف، صافي القيمة، مقارنة بالأسبوع الماضي.

**المرحلة ب:** السوق (عروض بيع/إيجار بين اللاعبين، انتهاء صلاحية، رسوم 4%، تأكيد مزدوج)،
المهام، لوحة الصدارة، الإشعارات داخل التطبيق.

**المرحلة ج:** لوحة الإدارة (أدوار: مشرف/مراجع/دعم، تعديل رصيد بسبب إلزامي، سجل تدقيق
غير قابل للتعديل، تصدير CSV)، الزمن الحقيقي (حضور اللاعبين على الخريطة).

### 8· الخريطة ثلاثية الأبعاد — **مُنفَّذة في Three.js**

> حُسم القرار: **Three.js (r150.1، مُضمَّن محلياً، 154 KB مضغوطة)** مع سقوط آمن إلى الشبكة
> عند غياب WebGL. الوصف التالي هو المواصفة التي بُني عليها `apps/ofuq/src/scene.js`.

المطلوب محرك أيزومتريك بـ WebGL، بلا أي اعتماد على شبكة خارجية (لا CDN):
- كل قطعة بلاطة معزولة العمق، وكل مبنى من 2–4 طبقات (قاعدة، جسم، سطح، تفاصيل).
- الإضاءة من مصدر واحد (شمال-غرب)، الظل `box-shadow` ثابت الاتجاه.
- مستويات المبنى تُقرأ من ارتفاعه: L1 منخفض، L5 برج صغير — **الشكل يعكس البيانات**.
- كل الرسم يُشتق من `store.snapshot()` فقط: `{assetId, level, districtId}`. لا حالة في
  المشهد نفسه. ولهذا يعمل المحرك كما هو في الوضع المحلي وفي الوضع المشترك.
- الأداء: لا يزيد عدد عناصر DOM المرسومة عن 100 قطعة × 4 طبقات، ويُستثنى ما هو خارج
  إطار العرض. الهدف 60fps على هاتف متوسط، و30fps كحد أدنى.
- بوابة القبول: مشهد كامل يرسم ويحدّث عند الشراء/التطوير/الترقية، واختبارات النموذج تعمل
  في Node بلا WebGL (THREE يُمرَّر كوسيط، لا يُستورَد داخل `scene.js`).
- **السقوط الآمن**: بلا WebGL يظهر نص «العرض ثلاثي الأبعاد غير متاح» + الشبكة + الخريطة
  المصغّرة (2D canvas) — كل الوظائف تبقى متاحة.

### 9· الحسابات والأمان

- بريد + كلمة مرور أولاً. Google/Apple لاحقاً بقرار صريح (يحتاج مزوّد هوية ونطاقاً).
- الجلسة تُستعاد عند الإقلاع، وتنتهي بوضوح مع رسالة «انتهت الجلسة، سجّل الدخول».
- RLS: قراءة الخريطة عامة، وكل قراءة أخرى مقيدة بالمالك، وكل كتابة عبر RPC فقط.
- لا مفاتيح سرية في العميل أبداً — المفتاح المنشور فقط، والتدقيق يفشل البناء إن ظهر غيره.
- لا `innerHTML` بمدخلات لاعب: النص عبر `textContent` أو مُهرِّب واحد مركزي.
- كل تعديل إداري يمرّ بدفتر مع سبب وهوية منفّذ ولا يُحذف.

### 10· PWA والأداء والوصولية والتعريب

- PWA: يعمل بلا شبكة على الشاشة الأخيرة المعروفة، مع شارة واضحة أن البيانات قديمة.
- الميزانية: JS أولي ≤ 120KB مضغوط، الخطوط ≤ 90KB، أول رسم ≤ 2.5s على 4G.
- WCAG AA: تباين ≥ 4.5:1، ترتيب تركيز منطقي، `aria-live` للتوستات، احترام تقليل الحركة.
- التعريب: عربي RTL أولاً، مفاتيح نصية في ملف واحد، وأرقام/عملة حسب اللغة. الإنجليزية
  واجهة ثانية، لا ترجمة آلية داخل الكود.

### 11· القواعد الصارمة (مخالفتها تراجع)

1. لا `localStorage` كمصدر حقيقة عند وجود جلسة — مجرد ذاكرة عرض.
2. لا تلاعب بالرصيد في العميل. أبداً.
3. لا NFTs ولا بلوكشين ولا «استثمار حقيقي».
4. صيغة الإخلاء ثابتة: «قيمة افتراضية داخل اللعبة، غير قابلة للاستبدال بمال حقيقي».
5. لا زر بلا أثر. الزر المعطّل يشرح **لماذا**.
6. لا شارة «متصل» بلا جلسة مصادَق عليها.
7. لا رقم على الشاشة لا يمكن تفسيره من الدفتر.
8. لا إعادة تصميم لما يعمل بلا سبب مكتوب.
9. لا مكتبة جديدة بلا مبرر حجم.
10. لا قراءة/كتابة مباشرة لجداول اللعبة من العميل — RPC فقط.
11. كل طلب تعديل يحمل مفتاح `idempotency`.
12. كل خطأ = جملة عربية + توضيح أثره المالي.
13. كل شاشة تعمل بـ 320px عرضاً.
14. كل حالة فراغ لها نص وفعل مقترح.
15. لا حركة بلا `prefers-reduced-motion`.
16. لا انتظار غير مرئي: كل عملية > 400ms لها مؤشر.
17. كل رقم مالي يُنسّق موحّداً (9,999 / 12.5K).
18. سقف إيجار 8 ساعات يُطبَّق على الخادم والعميل معاً.
19. الاختبارات أولاً للاقتصاد: أي معادلة جديدة تُختبَر قبل ربطها بالواجهة.
20. كل مرحلة تنتهي بتقرير: ما نُفّذ، ما لم يُنفَّذ، ما لم يُختبر على خادم حقيقي.

### 12· المراحل ومعايير القبول

| المرحلة | المخرَج | معيار القبول |
| --- | --- | --- |
| 1 · ربط الهوية | شاشة دخول/إنشاء/استعادة جلسة | لا يُعرض «مدينة مشتركة» بلا جلسة؛ إعادة الإقلاع تحفظ الدخول |
| 2 · الخريطة | 5 أحياء، 100 قطعة، تكبير/بحث/مرشّح/مصغّرة | كل حالة قطعة تطابق `ofuq_plots` وليست تمثيلاً محلياً |
| 3 · لوحة القطعة | تطوير/ترقية/تحصيل/بيع عبر RPC | ضغط مزدوج لا يخصم مرتين؛ السقف 8 ساعات مطبَّق |
| 4 · المحفظة | دفتر كامل + تصفية | مجموع البنود = الرصيد بالضبط |
| 5 · المشهد 2.5D | رسم أيزومتريك من اللقطة | الفتح/التطوير/الترقية يُعيد رسم المشهد بلا WebGL |
| 6 · السوق والمهام | عروض بين اللاعبين + مهام أسبوعية | عرض لا يُقبل مرتين؛ الرسوم 4% في الدفتر |
| 7 · الإدارة والزمن الحقيقي | لوحة أدوار + حضور | كل تعديل إداري له سبب ومدقّق وهوية |

**في نهاية كل مرحلة سلّم:** `npm run verify` أخضر، ولقطة قبل/بعد، وقائمة صريحة بما لم يُنفَّذ.

### 13· صيغة التقرير التي أريدها منك

```

ما لم يُنفَّذ:    (ولماذا)
ما لم يُختبر:    (مثال: SQL لم يُشغَّل على قاعدة حقيقية)
الأرقام:         (اختبارات ناجحة/فاشلة، حجم البناء)
المخاطر:         (ما قد ينكسر ولماذا)
```
